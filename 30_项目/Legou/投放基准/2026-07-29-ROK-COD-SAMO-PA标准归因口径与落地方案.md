# ROK / COD（SAMO）PA 标准、归因口径与落地方案

## 结论先行

1. 现有数值门槛已经明确，但“消耗”和“ROI7”是否基于同一个评价对象尚未明确。AppLovin Media 提供素材级花费，Reporting 提供 Creative Set / 广告组收入和 ROAS，两者不能直接拼成单 PA 结论。
2. ROK 有单 PA 投放，但同层级样本小且回收弱；COD/SAMO 当前没有可用的基础版单 PA 投放。问题不只是门槛高，而是部分项目缺少能验证门槛的测试单元。
3. 视频+PA 可以评价整个组合是否可跑，也能在严格控制其他变量时比较不同 PA；不能证明 PA 自身的独立 ROAS，更不能单独证明副玩法适合进入游戏新前期。
4. 现有 T0/T1 可保留为结果目标，但必须补齐评价对象、测试结构、统计周期、成熟度和数据来源。
5. 2026-07-30 会议进一步确认，业务判断应以纯 PA 消耗和 ROI 为主，视频+PA 不能作为 PA 自身通过的证据；但该次会议出现的 T0/T1 数字与 2026-07-24 项目标准不同，仍需确认各自适用范围。

## 一、现行标准原文

来源：用户于 2026-07-29 提供的截图；同样内容已出现在 2026-07-24 乐狗与莉莉丝关键业务双周会。

| 等级 | ROK 原文 | SAMO 原文 |
|---|---|---|
| T0 | 消耗：5 万美元；ROI7 >= 7% | 消耗：2.5 万美元；AND ROI7 >= 8.5%；iOS ROI >= 2.8% |
| T1 | 消耗：8,000 美元；ROI7 >= 6% 或成本比常规广告低 25% | 截图未提供 |

原文尚未说明：

- ROK T1 是否为“消耗 >= 8,000 且（ROI7 >= 6% 或成本低 25%）”。
- “成本”指 CPI、CAC、付费成本，还是其他指标；对照组和统计周期是什么。
- `ROI7` 是否等同 AppLovin D7 ROAS，收入是 IAP、广告收入还是 total revenue。
- SAMO 的“iOS ROI”观察窗口、收入范围和评价层级。
- 消耗门槛是单月、固定测试期、累计全生命周期，还是单个广告组生命周期。

## 二、近期 PA 证据

### 双周会记录

- 2026-06-05：会议称“灵能觉醒跑量占优，且 ROI 优于 SAMO AppLovin 广告整体”，但未注明是 PA 素材、视频+PA Creative Set，还是广告组口径。
- 2026-07-10：会议改述为“灵能觉醒是 SAMO PA 素材中最吸量的，但是回收一般”，并提出“消耗和回收都达标后推进到新前期”。
- 2026-07-24：正式记录 ROK 与 SAMO 的 PA 门槛，但未写统计对象、投放形式和数据来源。

“ROI 较好”和“回收一般”可能描述不同组合、区间或数据层级，不应在口径未确认前视为冲突。

限制：7 月末数据当时尚未全部跨过 D7；Media 花费不能做 Reporting ROAS 分母；视频+PA 收入不能归为 PA 独立贡献；当前成员关系不能替代历史成员快照。

### 数据所揭示的矛盾

ROK“吸沙卖水”：

- 如果 8,000 美元门槛采用 Media 花费，2026 年 7 月已经达到 T1 消耗线。
- 如果采用单 PA Reporting 花费，同期只有 739.41 美元，远未达到 8,000 美元。
- 6 月单 PA D7 为 0%，视频+PA D7 为 15.42%，组合跑出不等于 PA 自身跑出。

COD/SAMO“灵能觉醒”：

- Media 花费远高于 2.5 万美元，但没有可用的基础版单 PA 测试单元。
- 不能说“灵能觉醒单 PA 已达到或未达到 T0”；只能说素材有规模，已知视频+PA 组合未形成稳定达到 8.5% 的证据，单 PA 尚不可验证。

## 三、各层数据的结论权限

| 数据层级 | 能回答 | 不能回答 |
|---|---|---|
| Media / Asset 花费 | 素材关联了多少消耗、是否有量级 | 单条 PA 的收入和 ROAS |
| 单 PA Creative Set | 只有该 PA 的投放单元整体回收 | PA 的严格因果增量 |
| 视频+单 PA Creative Set | 视频与该 PA 组合后的商业表现 | PA 独立 ROAS |
| 多视频+多 PA Creative Set | 混合投放单元整体是否可跑 | 任一成员的独立贡献 |
| 同视频、不同 PA 的 A/B | 控制其他变量后，不同 PA 的相对差异 | 无对照时的绝对因果贡献 |
| 视频-only vs 视频+PA | PA 对组合结果的增量影响 | 跨账号、跨周期直接外推 |

## 四、当前标准为什么难落地

1. **评价对象不一致**：素材级花费与 Creative Set 级回收不能直接合并。
2. **投放结构不支持验证**：ROK 单 PA 样本小；COD/SAMO 没有基础版单 PA。若主要投视频+PA，应明确考核“组合”。
3. **起量失败与回收失败混在一起**：未拿到足够消耗可判为“量级未通过”或“样本不足”，不能自动推导为“回收未通过”。
4. **研发目标不同于纯 UA**：乐狗还要用 PA 探索副玩法和新前期。推进产品前期时，应同时看 PA 开始率、有效操作率、完成率、试玩后点击/安装，以及进入产品后的 D1/D7、付费和关键行为承接。

## 五、建议落地方式

### 结论状态

| 状态 | 含义 |
|---|---|
| 不可测 | 没有符合标准的投放单元或历史成员证据 |
| 样本不足 | 已投放，但同层级花费未达到最低样本 |
| 量级未通过 | 在约定预算、周期和投放条件下仍无法获得规模 |
| 回收未通过 | 同一评价单元的成熟 D7 低于门槛 |
| 组合通过 | 视频+PA 组合达到标准，但不代表 PA 独立通过 |
| PA 通过 | 单 PA 或严格控制实验达到标准 |

### 三层标准

1. **测试资格层**：固定项目、账号、市场、系统、周期、预算、优化目标和评价单元；同层级花费达到最低样本后，才判断回收。
2. **商业结果层**：单 PA 与视频+PA 分开评价；T0/T1 必须应用到同一投放单元的花费和成熟 ROI7。
3. **产品决策层**：推进新前期时，再加 PA 行为与产品承接数据。

### 最小测试结构

- 独立单 PA Set，每个 Set 只放一个目标 PA。
- 固定宿主视频的 A/B：视频-only、视频+PA A、视频+PA B。
- 国家、系统、出价目标、预算、时间和版本尽量一致。
- Reporting 按日保留 `account_id + app + campaign_id + creative_set_id + creative_type + OS + country` 的花费、收入和 D0/D7。
- 保存 Creative Set 成员历史及生效时间，不能只保存当前成员。
- 混合多视频、多 PA 的经营 Set 可继续跑量，但不进入单 PA 达标判断。

## 六、需要莉莉丝确认的问题

1. 标准评价的是 PA 素材、单 PA Creative Set、视频+PA 组合，还是广告组/项目整体？
2. 视频+PA 达标能否算 PA 达标？如果可以，是否应命名为“组合标准”？
3. 消耗门槛采用 Media 素材花费还是 Reporting 投放单元花费？花费和 ROI7 是否必须来自同一对象？
4. ROK T1 的准确逻辑是什么？“成本低 25%”中的成本、对照组和周期是什么？
5. ROI7 的收入范围、归因窗口、时区、币种、成熟规则是什么？SAMO 的 iOS ROI 是哪一日指标？
6. 未达到最低消耗时，是“量级未通过”还是“样本不足”？是否提供固定测试预算和周期？
7. COD/SAMO 后续是否建立单 PA 测试 Set；若不建立，采用什么替代标准？
8. 莉莉丝可提供哪些数据：Media 花费、成员历史、Reporting 花费/收入/ROAS、OS/地区拆分？
9. PA 推进新前期时，双方共同认可的试玩行为和产品承接指标是什么？
10. 谁负责出具最终结论，并触发继续、迭代或停止？

## 七、给莉莉丝的沟通版本

想跟大家一起把 PA 标准的统计口径和落地方式先对齐一下。我们不是对标准数值本身有异议，主要是现在的投放结构和后台数据层级还没有完全对应，容易出现“素材消耗达到门槛，但没有同层级 ROAS 可以核”的情况。为了后续研发侧能按同一套规则选型和复盘，想请大家帮忙确认几个问题：

1. 目前 ROK 有单 PA 投放，但量比较小、回收也比较弱；COD/SAMO 目前没有基础版单 PA 投放。现有 8,000 / 50,000 / 25,000 美元门槛，具体是看 Media 素材消耗，还是看单 PA / 视频+PA Creative Set 消耗？一直拿不到门槛消耗时，应判断为量级未通过，还是样本不足？
2. 目前有回收的结果主要来自视频+PA。这个数据可以说明整个广告组合是否能跑，但视频和 PA 的贡献拆不开。视频+PA 达标是否可以算 PA 达标；如果可以，是否需要单独定义为“组合标准”？
3. Media 可以看到素材级聚合消耗，Reporting 可以看到 Creative Set / 广告组消耗和 ROAS，两边数据都准确，但评价层级不同。现有标准准备以哪一层为准，后续用什么固定报表或测试结构复盘？
4. 是否可以给重点 PA 建独立单 PA Set，并补一组同视频下的 video-only / video+PA 对照？这样量级、组合价值和 PA 增量可以分别判断。
5. 还想一起补齐 ROI7、iOS ROI、成本低 25% 的具体口径，以及 PA 推进新前期时需要同时满足的试玩行为和产品承接指标。

希望最后一起确认一张统一口径表、一套可复用测试结构和一份双方都能复核的数据报表。这样每条 PA 是继续、迭代还是停止，结论会更稳定，也能减少重复解释。

## 八、2026-07-30 至 08-05 补充核验

### 已进一步确认的口径

- 2026-07-30 的 PA 后续计划明确区分纯 PA 与视频+PA。纯 PA 是否达标，应使用纯 PA 投放单元的消耗和成熟 ROI；视频+PA 只能判定组合。
- AppLovin 的 Media 报表可能在 PA 作为视频尾卡时记录关联花费，即使用户不一定实际进入 PA，因此 Media 花费不能自动视为纯 PA 花费。
- 不同渠道的成本和回收不能直接横向判定高低，需要在渠道内部使用一致市场、系统、周期和优化目标比较。
- 定制商店页、专属承接视频和产品新前期改造，应在 PA 通过核心商业标准后再投入。

### 数字标准仍有范围冲突

2026-07-30 会议纪要出现“T1 单渠道消耗 5,000 美元”和“成本低约 30%”等表述，与 2026-07-24 记录的 ROK T1 8,000 美元、成本低 25% 不同。两者可能分别对应通用分级、不同项目或不同版本，不应直接覆盖。后续需要负责人给出“项目、渠道、评价对象、版本、生效日期”五项映射。

### 项目判断更新

**COD/SAMO 灵能觉醒：**

- 6 月会议曾因相对吸量和阶段 ROI 表现给出乐观判断；7 月 10 日已调整为“吸量较好但回收一般”。
- 7 月 30 日会议按当时 T0/T1 规则判定其未通过。当前执行上应视为“未通过、暂不推进”，不能再沿用 6 月的“可扩量”结论。
- 数据审计仍未找到可用的基础版单 PA Set，所以“业务判定未通过”成立，但 PA 自身独立 ROAS 仍不可验证。

**MiniMart：**

- 已有 4 条视频和 3 条 PA。Facebook 侧成本有优势但 ROI 未通过；AppLovin 侧 ROI 通过但成本优势不明显。
- 视频素材达到 T0 不等于 PA 达到 T0；当前 PA 混合视频表现较好，但纯 PA 尚未通过。
- 下一步应补 Google 测试和纯 PA 测试结构，再判断是否投入定制商店页或产品承接改造。

**ROK 新方向：**

- 8 月 5 日选型会继续评估护送模拟经营、划线圈地、点击轻策略和划线卡牌部署。
- 会议记录显示历史纯战斗 PA 整体偏弱。下一轮应优先验证模拟经营后勤、资源扩建/地图展开和低理解成本的划线圈地，纯战斗方向降低优先级。
- 护送方向在 Google 两周消耗约 12,000、ROI 一般，只能作为继续拆解玩法结构的线索，不能直接判定通过。

完整飞书资料入口和会议时间线见 [[2026-05至08-乐狗PA飞书资料索引与决策知识]]。

## 九、证据强度与下一步

- 标准数值与 2026-07-24 双周会：高证据。
- Media 素材花费：高证据，属于 AppLovin 素材级官方值。
- 2026-07-28 的 Creative Set ROAS：中低到中证据；历史成员证据不完整时只能作为关联代理。
- “当前标准无法直接落到单素材”：高证据，由数据层级和投放结构共同决定。
- “某条 PA 本身带来多少收入”：当前不可证。

下一步优先确认“评价对象 + 数据源 + 测试单元”。在这三项明确前，不建议只围绕 8,000、25,000 或 50,000 美元争论高低。
