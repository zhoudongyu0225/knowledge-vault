# 从 13 份行业资料提炼的个人提升框架

## 定位

这份笔记不要求所有内容都服务于当前工作。它提炼的是可以迁移到研究、学习、投资、职业选择和个人项目的能力：

1. 识别证据。
2. 拆解复杂系统。
3. 管理不确定性。
4. 复核数字和概念。
5. 形成长期学习闭环。

主要方法来源于 [[【2026年游戏运营篇】三米星球原创专栏.pdf]]，再用本批其它报告和截图检验其可靠性。

## 一、先提高“相信什么”的能力

### 证据卡

任何数字或观点进入长期记忆前，先记录：

```text
主张：
来源：
时间：
地区：
平台：
样本：
指标定义：
分母：
证据等级：
可以回答：
不能回答：
替代解释：
验证方法：
```

本批资料为什么需要这张卡：

- Sensor Tower 标题是 2025，数据期其实是 2024。
- “前三个月活动图”只画了 42 天。
- Puzzle 和留存截图没有数据期、地区、平台和样本。
- DataEye 报告多处合计、占比和表格行数冲突。
- 三米星球把 7 日收入/新增用户称作 LTV，把收入/投放称作 ROI，概念不准确。

### 事实、推断、预测分栏

示例：

| 类型 | 内容 |
|---|---|
| 事实 | 2024 全球游戏下载 49.3B，报告口径同比下降约 6.6% |
| 推断 | 市场增长重心从新增安装转向存量参与和变现 |
| 预测 | 未来长线运营的重要性会继续提高 |

分栏能避免把合理推断误记成已经验证的事实。

## 二、用系统图代替功能清单

WhiteOut 案例说明，理解复杂对象不能只列出“火炉、建筑、英雄、探险、联盟”，而要看它们怎样互相推动。

通用拆解：

```text
外部压力
-> 目标
-> 资源
-> 行动
-> 反馈
-> 新能力
-> 下一个目标
```

可以迁移到：

- 学习一门新技能。
- 经营个人项目。
- 分析一家公司。
- 规划健康和运动。
- 理解投资标的的增长和约束。

练习方法：对一个熟悉的问题画出 10 个节点和节点之间的箭头，找出真正的瓶颈，而不是继续增加待办。

## 三、用分阶段漏斗管理不确定性

Voodoo 第三方案例最值得保留的不是门槛，而是投入顺序：

```text
廉价探索
-> 初步行为证据
-> 更深内容证据
-> 经济性证据
-> 扩大资源
```

个人应用：

| 场景 | 低成本验证 | 升级投入条件 |
|---|---|---|
| 学一项技能 | 先完成一个小作品 | 能独立解决真实问题 |
| 做个人项目 | 先做可用原型 | 有真实使用和重复需求 |
| 写长文或课程 | 先写提纲和短篇 | 有反馈且核心观点成立 |
| 研究投资标的 | 先做证据卡和反方假设 | 关键财务、估值和风险过关 |
| 购买昂贵工具 | 先试用或租用 | 使用频率和节省时间被证明 |

原则：资源应随证据增加，而不是随热情增加。

## 四、提高数字和概念的卫生程度

### 小游戏测算图复核

原图：[[20251230_小游戏数据测算.png]]。

图中数字：

- 消耗：1000 万。
- 流水：1000 万。
- 分成后：600 万。
- 基础激励金：100 万。
- 投放激励金：50 万。
- 新游戏激励金：400 万。
- 广告金收益：1150 万。
- 研发分成前 ROI：115%。
- 另写“全吃满微信小游戏实际回收 85%”。

名义算术可以复核：

```text
分成比例 = 600 / 1000 = 60%
激励合计 = 100 + 50 + 400 = 550 万
名义回收 = 600 + 550 = 1150 万
名义回收率 = 1150 / 1000 = 115%
```

其中“千万流水 100% 回本”对应：

```text
600 万分成后收入 + 400 万新游戏激励 = 1000 万
```

但“实际回收 85%”意味着只回收 850 万，比名义 1150 万少 300 万。图片没有解释这 300 万是研发分成、首发让利、税费、确认失败、到账折损还是其它成本。

因此这张图只能保存为待补全的情景测算，不能作为微信小游戏回收 Benchmark。

### 更可靠的收益瀑布

```text
用户支付流水
- 渠道分成
- 税费和退款
= 可确认净流水
+ 确认可获得的激励
- 广告投放
- 研发分成
- 发行和运营成本
- 资金时间成本
= 实际贡献利润
```

每一项还要记录：

- 确认条件。
- 封顶金额。
- 到账时间。
- 是否可重复。
- 是否与其它激励互斥。

### 常见概念分开

| 概念 | 简化定义 |
|---|---|
| ROAS | 广告归因收入 / 广告花费 |
| ROI | 利润或净收益 / 总投入，使用前必须写清分子分母 |
| ARPU | 某周期总收入 / 该周期用户数 |
| LTV | 一个 cohort 在完整或预测生命周期中的累计价值 |
| 留存 | 在定义时间点仍满足活跃条件的 cohort 用户比例 |
| 排名变化 | 榜单位置变化，不等于收入变化率 |

## 五、建立可重复的复盘闭环

三米星球专栏中最稳健的方法是：

```text
目标
-> 清单
-> 执行
-> 数据
-> PDCA
-> 复盘
```

活动复盘的 12 个维度也可以迁移到个人项目：

1. 目的。
2. 时间。
3. 主题。
4. 规则。
5. 奖励。
6. 传播。
7. 成本。
8. 风险。
9. 数据。
10. 结论。
11. 节奏。
12. 执行。

个人复盘最少记录：

```text
原目标
实际结果
关键证据
发生偏差的原因
哪些判断被证伪
下次保留什么
下次停止什么
下一步最小动作
```

## 六、从“知道”走到“能教”

专栏提出的学习闭环：

```text
学习 -> 练习 -> 实践 -> 教学
```

四个阶段的验收：

| 阶段 | 验收 |
|---|---|
| 学习 | 能用自己的语言解释 |
| 练习 | 能在限定案例中使用 |
| 实践 | 能处理真实约束和失败 |
| 教学 | 能说明边界、常见错误和判断标准 |

仅收藏和划线停留在输入阶段；写出能被别人使用的说明，才暴露自己是否真正理解。

## 七、职业能力采用 T 型结构

三米星球专栏把运营放在研发、市场、运营和平台支持的协作系统中，并覆盖内容、活动、用户、版本和数据。

更可靠的个人策略：

- 选一项能形成明显优势的纵向能力。
- 保留足够的横向能力与其它角色协作。
- 用作品、复盘和决策记录证明能力，而不是只列课程和名词。

职业选择闭环：

```text
收集 JD 样本
-> 提取高频能力
-> 找差距
-> 做作品证据
-> 面试复盘
-> 按直属领导、薪资、挑战、附加价值加权选择
```

专栏中的公司名单、题库、薪资、云游戏预测和课程案例会过期，只保留方法，不保留为当前市场事实。

## 八、只自动化重复且有价值的工作

专栏 p.66 的这条原则值得长期保留：

- 重复但低价值：先考虑删除。
- 高价值但低频：先保留人工判断。
- 高频且高价值：标准化输入、输出和验收，再自动化。
- 尚未稳定：不要急着沉淀成复杂系统或 Skill。

这和知识库维护一致：先解决真实问题，再把高频工作沉淀成模板或 Skill。

## 30 天个人练习

### 第 1 周：证据

- 每天选一张数据图，写一张证据卡。
- 至少复算一个百分比或合计。
- 写出两个替代解释。

### 第 2 周：系统

- 选一个熟悉问题，画因果图或依赖图。
- 标出主轴、并行准备、软卡点和硬卡点。
- 删除一个不能推动目标的待办。

### 第 3 周：实验

- 选一个小目标，设计低成本验证。
- 预先写清继续、停止和加码条件。
- 结束后对比预判与结果。

### 第 4 周：输出

- 把前三周最有价值的内容写成一页说明。
- 让一个不了解背景的人阅读。
- 根据对方的误解补充边界和例子。

完成标准不是写了多少，而是留下：

- 4 至 7 张合格证据卡。
- 1 张系统图。
- 1 次有预设阈值的实验。
- 1 份别人能理解和使用的说明。

## 对三米星球专栏的判断

### 值得保留

- 生命周期和多角色协作框架。
- 清单、PDCA、结构化和瓶颈思维。
- 活动复盘的 12 个维度。
- 学习、练习、实践、教学。
- 只优化重复且有价值的工作。
- JD、作品证据、面试复盘、Offer 加权选择。

### 不能直接使用

- 作者履历、会员数量和案例成功率未经独立证明。
- 云游戏预测和求职数据较旧。
- 买量和直播章节主要是占位或导流。
- “获新成本是召回 5 倍”“留存提高 5%带来利润提高 25%”缺少来源。
- 私域章节建议收集电话、收入、星座等资料，但没有同意、最小化和保留期限规则。
- p.90 至 p.93 对 ROI、LTV 和收入公式存在概念或量纲错误。
- 后 20 页以会员、课程和社群推广为主，不能作为方法有效性的证据。

## 我的长期使用规则

以后调用这批资料时：

1. 先读取对应专题，不先打开全部原始文件。
2. 涉及预算和经营门槛时，只使用有明确口径的项目数据。
3. 外部报告用于生成假设，不替代验证。
4. 截图用于发现信号，不直接升级为结论。
5. 任何被真实项目证伪的规则，都要在知识库中标记废弃或修订。
